Cross-language, contract first

A pet store, moved from Next.js to FastAPI without moving its API

A refactoring preserves what a function does. A translation preserves a signature. Rewriting a service in another language has to preserve the only thing anyone outside the repository can see: the HTTP contract. A caller does not import your functions. It sends PATCH /pets/42 with a JSON body and expects 200.

Everything below is one worked example: eight route files, thirteen operations, five request schemas, and every shape a CRUD API has — a collection, a member, a sub-collection, a sub-member, a whole-resource replacement, an action that is not CRUD at all, an aggregate, and a catch-all that matches across slashes.

Generated  The contract and every translation on this page were produced by running fr over tests/petstore, captured by cargo test --test site_data. Nothing here is typed by hand, so nothing here can drift from what the tool does.

The method

The two frameworks are not mirror images, and the difference decides the order of the steps.

FastAPI derives OpenAPI from the code. The path decorator gives the URL and the method, the annotated parameters give the path and query parameters, a Pydantic model gives the body schema, and /openapi.json falls out. The contract is not a document somebody maintains; it is a projection of the types.

Next.js does not. The App Router has no equivalent. The URL is the file's position on disk, the method is the exported function's name, the body is whatever a zod schema in some other module validates, and the query parameters are read out of the URL by hand. None of it is declared.

So the rewrite goes in one direction and the checking goes in the other:

  1. Derive the contract from the tree, before touching anything. fr openapi --yaml > contract.yaml. This is the baseline, and it is the step most teams have skipped, which is why the rewrite that follows has nothing to be wrong about.
  2. Translate route by route. fr translate app/api/pets/[petId]/route.ts fastapi. Read the report each time: what carried, what did not, and which status codes are returned but not declared.
  3. Finish the handlers. The database calls and helpers the route imported have no counterpart and are yours. The tool did the mechanical, error-prone half — the half where a mistyped path segment costs you a week and a missing :path costs you the requests nobody reports.
  4. Run the service and diff. curl -s localhost:8000/openapi.json | … against the baseline. Every difference is a defect until argued otherwise.

The failure this catches is the one nothing else catches: a contract that quietly got smaller. A smaller contract looks exactly like a correct one. Every test you have will pass, and the requests that stop working are the ones nobody sends often.

The one thing that moves

A Next.js handler receives (request, context) and digs the path parameter out of context.params.petId. FastAPI passes it as an argument. So the value arrives by a different route and every use of it moves with the parameter — that is the behaviour being redistributed while the URL it answers stays exactly the same: 

// Next.js
const pet = await db.pet.findUnique({ where: { id: context.params.petId } })

# FastAPI
pet = await db.pet.findUnique({"where": {"id": pet_id}})

Rewriting the declaration and leaving context.params.petId in the body would produce a file that parses, imports and starts — and answers every request with a NameError.

The contract

Derived from the tree, before the rewrite. Paths, methods and path parameters are exact, because they come from where the files sit. Schemas are as good as what the source declared. Responses are default only. Which status an endpoint returns is a fact about its code, not about its declaration, and writing 200 for everything would put fiction into the file you are about to diff against.

Every endpoint, both sides

One command each, in the order a reader meets them. The Python is what fr translate produced; the report beside it is what the tool said about the parts it could not carry.

Did the contract survive?

The method says to run the finished service and diff its /openapi.json against the baseline. This is the half you can check without running anything: fr openapi reads the other side too — the decorators and the signatures a FastAPI router declares — so the same command answers the same question about the code the rewrite produced.

Thirteen operations went in and thirteen came out — every URL, every method, every path parameter and every query parameter identical. Nothing was lost and nothing was invented.

That is the claim the build holds to: the site data test asserts the two documents agree, so a translation that started dropping endpoints or reshaping paths would fail the build and not merely the page.

What it does not say

The two documents agreeing means the crossing was faithful. It does not mean the contract is complete, and the difference matters more than anything else on this page: both sides can be missing the same thing and agree perfectly.

So the baseline says what it could not read. A statement the tool carries whole is a statement it did not look inside, and a query parameter read in there is missing from the document. That is why the note exists, and why it counts. It is in the What it does not settle pane above, and the count is the number to watch. A gap that announces itself is a gap you can close; a gap that does not is the thing this whole document exists to prevent.

This example has closed twice while it was being written. It read two statements the tool could not follow, and they were these: 

const limit = Number(req.nextUrl.searchParams.get("limit") ?? "50")

const pets = await db.pet.findMany({
  where: species ? { species } : {},
  …
})

?? asks whether a value is absent, which is a question and not an arithmetic operator: Zig spells it orelse, Rust reaches for Option::unwrap_or, Java for a static method, Python has to name the value twice, and Go cannot say it at all. And { species } is the shorthand every modern TypeScript file is written in — it means { species: species }, and not reading it refused the whole object, and with it the statement the object was in.

Both are read now, the note is gone, and limit is on both sides of the crossing. That is what closing a gap looks like from here: the count goes down, and the contract gets bigger.

Where it stops

Not a proof. Preserving the addressing half of a contract — the URLs, the methods, the path parameters — is a syntactic property and the tool can be held to it. Preserving the shape half needs to know what the handlers do, and the handlers are the part carried across for a person to finish.

Not a migration. Authentication, database access, middleware ordering and every library the route imported have no counterpart and are reported, not translated.

Not the other direction. FastAPI → Next.js loses a machine-readable contract rather than gaining one: nothing in the target regenerates it, so it would have to be exported before the rewrite and asserted against afterwards. This tool does not do that direction.

Read the notes. Everything the document could not settle is printed beside it rather than guessed at, because a baseline that quietly invents an entry is the worst possible outcome: the diff comes out clean and the contract still shrank.
