Refactoring that tells you
what it could not prove.

Rename a symbol across Go, TypeScript, Rust, Python and a Helm chart at once. Every reference it finds carries the evidence that found it — and only the references it can justify are rewritten. The rest are handed back as a list.

The tag on the right is the point

A textual rename is fast and wrong. A compiler-backed one is right and exists for one language. This sits in between on purpose: it resolves what the syntax proves, labels every answer with the rule that produced it, and refuses to rewrite anything weaker than proof.

exact and import-qualified are rewritten. field-based and name-only are reported for you to check. Nothing is guessed.

helm/helm @ a8ab76e
fr refs pkg/action/action.go:725:6
5 reference(s) to determineReleaseSSApplyMethod

It reads the configuration too

A Helm chart is a values file and templates that read it — a dataflow no compiler sees. Rename a values key and the templates that use it move with it, while {{ .Release.Name }} is left alone, because it is the same word and a different thing.

alpine chart
fr rename testcharts/alpine/values.yaml:1:1 appName
-  name: "{{.Release.Name}}-{{.Values.Name}}"
+  name: "{{.Release.Name}}-{{.Values.appName}}"
-    values: {{.Values.Name}}
+    values: {{.Values.appName}}

Name → appName: 3 site(s) across 2 file(s)

Not changed — review these yourself:
  textual-occurrence (1):
    alpine-pod.yaml:3:17  'Name' appears in a string or comment; left unchanged
