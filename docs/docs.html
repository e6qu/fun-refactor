Install

git clone https://github.com/e6qu/fun-refactor
cargo install --path fun-refactor   # installs `fr`

Rust 2021 edition and a C compiler — every tree-sitter grammar is C, so a cold build takes a few minutes.

Naming a target

Commands that act on a symbol take a target, written one of two ways.

FormWhenExample
path:line:col Always works. 1-based; must land on the identifier itself, at the definition or any use of it. fr refs pkg/action/action.go:725:6
a bare name When the name is unique in the workspace. Otherwise the tool lists the candidates and stops. fr callers RunAll
path:l:c-l:c fr extract, which acts on a range rather than a symbol. fr extract a.go:8:5-8:19 count
path fr imports, and the destination argument of fr move. fr imports pkg/action/install.go

Relative paths are read against the workspace root — the current directory unless -C says otherwise — not against your shell's working directory. A path that does not exist is an error that says where it looked.

Confidence

Every resolved reference carries the rule that resolved it. This is the tool's central idea: it would rather hand you a list to check than change a line it cannot justify.

TierWhat proved itRewritten
exact The lexical scope chain, the same file, or the enclosing package. yes
import-qualified An import binding in this file names the file it came from. yes
field-based The name is a member of something, but the receiver's type is not tracked. no — reported
name-only Nothing but the name matched. no — reported

Refactorings also report textual occurrences — the name in a string or a comment — and parse errors, because a file that could not be read may hold references nobody can see.

Changing

All of these print a diff and write nothing until --write.

fr renameRename a symbol and everything that points at it
fr extractAn expression into a binding, or statements into a function
fr inlineThe reverse of either
fr signatureAdd, remove or reorder parameters, updating every call
fr moveMove a symbol to another file, carrying its imports
fr deleteDelete it, refusing while anything uses it
fr importsDrop unused imports and sort the rest
fr rewriteLocal transformations: invert-if, guard-clause, de-morgan
fr restructurePattern rewriting: old($X) → new($X)
fr remove-flagRetire a feature flag and the branch that served it

--json works on every command. fr capabilities prints the full matrix of what each language supports, with the reason attached to every cell that is not supported.

How it works

Parsing, and where the trees live

Each file is parsed by tree-sitter, one grammar per language, into a tree that keeps every byte — comments and whitespace included. That is what makes losslessness possible: an edit is a byte-range splice, so everything outside the range is untouched by construction.

The trees are not stored. They live for the duration of one file's extraction and are dropped; what survives is a much smaller set of facts — symbols, references, scopes, imports — each carrying a byte span. Keeping 16,000 syntax trees in memory would cost more than re-parsing the few files any one command needs.

Positions are byte offsets everywhere except the command line. Line and column are a display format, and a tool that miscounts a column corrupts a file.

Helm gets one extra step. A template action is masked before parsing — replaced by filler of exactly the same byte length — so the surrounding YAML still has valid structure and every offset stays correct. The actions are then parsed separately, which is how .Values.image.tag becomes a reference to a values key that a rename can rewrite.

The cache

Content-addressed. A file's facts are keyed by the SHA-256 of its contents combined with a fingerprint of the query set that produced them. Change the file and the key changes; change a query and every key changes. There is no invalidation logic to get wrong, because there is nothing to invalidate — a stale entry is simply never looked up. 

fr cache
location  ~/Library/Caches/fun-refactor/v2-dbe4d237fed430ca
size      3791 KiB

fr cache --clear
fr <command> --no-cache

Set FUN_REFACTOR_CACHE to override the location. The directory name carries a schema version, so a release that changes what a fact is starts a new namespace rather than reading old data with a new meaning.

The edit engine

Every refactoring returns a plan and touches nothing. The engine then:

  1. Rejects overlaps. Two edits to the same bytes are a bug in the caller, not something to resolve by picking one.
  2. Applies in descending offset order, so earlier offsets stay valid as it goes.
  3. Reparses every changed file and refuses the whole edit if the file parses cleanly now and would not afterwards.
  4. Commits atomically. Either every file is written or none is.

That reparse check is the net, not the safety. It cannot catch a change that parses and means something else — hoisting a statement out from under the condition that guarded it, or dropping the brackets a de Morgan result needs. Those are caught by the analysis being right, which is why the confidence tiers exist and why the tool refuses as much as it does.

Known limitations

BUGS.md lists every one, each with the measurement that established it. In summary: reachability under dynamic dispatch is undecidable from source and is reported rather than guessed; Helm values passed on a command line are invisible to a workspace scan unless you supply them with -f and --set; CSS classes named inside TSX helper calls are not resolved, which measurably costs about two-thirds of the reach of a stylesheet rename in a modern React codebase; and two upstream grammar gaps, in SCSS and in Go's handling of a user-defined new.
